# FRAME Stream Management

FRAME Stream Management is the control page for live video relay streams. It helps you create
stream links, check stream health, copy viewer/stat links, and connect stream data to overlays.

## Who This Is For

This tool is for streamers and operators who manage IRL or live production video feeds.

Use it if you need to:

- Create a new stream relay entry.
- Copy stream links for a camera, encoder, or player.
- Watch bitrate, latency, dropped packets, and uptime.
- Share read-only stream statistics.
- Connect BELABOX or other supported relay telemetry.
- Publish FRAME relay destinations and accounts to connected Belabox agents.
- Send stream status into FRAME Overlays.

## What You Use It For

Use Stream Management when you need to set up or monitor a live feed.

Common uses:

- Create publisher and player links for a stream.
- Check whether a stream is live and healthy.
- Copy a public read-only stats link.
- Create stats links for tools such as IRL+ Chat.
- Open Overlay Studio for stream-connected overlays.
- Add a BELABOX telemetry profile without changing the relay itself.
- Make self-hosted FRAME publisher accounts selectable in FRAME Remote belaUI.

## How To Install

Stream Management is part of the normal FRAME stack.

Recommended setup:

1. Open the FRAME folder.
2. Run `stack.cmd`.
3. Choose **Guided setup**.
4. Enable the video relay and stream management tools.
5. Start the stack.
6. Open Stream Management:

```text
http://localhost/slsui
```

For standalone testing only:

1. Open this folder:

```text
services/frame-streams
```

2. Copy `.env.example` to `.env`.
3. Set the receiver address and API key in `.env`.
4. Start the service:

```bash
docker compose up --build -d
```

Most users should use the full FRAME stack instead of standalone mode.

## How To Operate

Open:

```text
http://localhost/slsui
```

To create a FRAME relay stream:

1. Choose the option to add a stream.
2. Give it a clear name.
3. Copy the publisher link into your camera, encoder, or streaming device.
4. Copy the player link into the tool that will receive or preview the feed.
5. Watch the stream stats to confirm the feed is stable.

When Belabox Manager is enabled, SLS stream profiles with publisher keys are also exported to the
FRAME Remote belaUI relay list. The relay destination uses `PUBLIC_RELAY_HOST` and `SRTLA_PORT`,
while each profile name becomes a selectable relay account. Profiles without publisher keys are not
advertised to the Belabox.

To use BELABOX or another existing relay:

1. Add a custom telemetry profile.
2. Paste the supported stats URL or relay ID.
3. Confirm that stats appear in Stream Management.
4. Use the connected stats with overlays if needed.

Useful stats:

| Stat | What It Tells You |
| --- | --- |
| Bitrate | How much video data is coming in. |
| RTT | How quickly the connection responds. |
| Latency | How far behind live the feed is. |
| Dropped packets | Whether the connection is losing data. |
| Uptime | How long the feed has been active. |

If a stream looks unstable, lower the sending bitrate, improve the network connection, or move the
stream source closer to a stronger connection.

## Relies Upon

Stream Management relies on:

- FRAME Portal
- FRAME Edge
- FRAME Video Ingest for local SRT/SRTLA relay streams
- The receiver API key generated by FRAME setup
- The public SRTLA hostname configured as `PUBLIC_RELAY_HOST`
- FRAME Overlays when opening overlay tools from this page

Optional connections:

| Feature | Relies Upon |
| --- | --- |
| Public stats links | FRAME Edge and the configured public/Hybrid address |
| BELABOX telemetry | A reachable BELABOX-compatible stats source |
| FRAME relay accounts in remote belaUI | FRAME Belabox Manager |
| Overlay shortcuts | FRAME Overlays |

## Notes For Operators

The management page should stay local or login-protected.

Read-only stats links are safe to share when you want another tool to see stream health, but they
should not expose private management controls.

Custom telemetry profiles are stored in FRAME data so they survive restarts.

In Hybrid mode, `PUBLIC_RELAY_HOST` must be a public DNS name or IPv4 address that SRTLA senders can
reach. It is separate from the browser-facing Cloudflare hostname when those addresses route to
different endpoints.
